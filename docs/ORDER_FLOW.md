# 주문과 로그인 기준

## 로컬 장바구니와 카드

통합 장바구니는 [DATABASE](DATABASE.md)의 로컬 작업목록이다. AUTO 수량 `+/-`는 로컬 DB만 수정한다. 이 동작에서 웹사이트 접속, Playwright 실행, 네트워크 요청을 금지한다.

전체 주문은 [UI](UI.md)의 진행창에서 처리한다. AUTO는 연결된 판매처별 카드 하나, MANUAL_BROWSER는 상품 URL별 카드 하나다. 전체 시작 시 연결된 AUTO 판매처의 SQLite 주문 대상 스냅샷을 모두 저장한 다음 판매처별 장바구니 준비를 독립적으로 실행한다. 한 판매처의 실패가 다른 판매처를 막지 않는다. 푸드레인·우양의 사이트 연동은 아직 없다.

장바구니의 전체 주문하기는 확인창만 연다. 확인창 하단의 전체 주문 시작 또는 카드의 주문 시작에서 사이트 장바구니 준비를 시작한다. MANUAL 카드에서는 사용자의 사이트 주문 동작을 기다린다. AUTO 무료배송 기준 미달은 개별/전체 진행 모두 주문 불가로 유지한다.

주문 시작 전에는 원래 장바구니 항목을 공유하여 수량 변경/AUTO `+/-` 및 상품 X 삭제를 즉시 반영한다. 사이트 준비를 시작한 대상은 모델에서도 편집을 잠근다. 진행창을 닫으면 편집 잠금을 해제하지만 사이트의 주문/결제 여부를 추측하지 않는다.

사이트 장바구니 일치는 `READY`다. 준비 후 같은 판매처 프로필의 Edge 창을 하나씩 열고 `[다음 판매처 열기]`로 다음 READY 장바구니를 연다. `[사이트 확인]`은 이전에 창을 연 이력이 있어도 현재 사이트 장바구니를 읽기 전용으로 다시 확인한다. 저장 대상·옵션·수량이 일치하면 READY, 다르면 확인 필요 상태로 남긴다. `BROWSER_OPENED`는 창을 연 이력이지 주문 완료가 아니다. 사용자가 명시적으로 `[전체 주문 시작]` 또는 카드의 `[새 주문 준비]`를 선택할 때만 현재 로컬 장바구니의 새 스냅샷을 저장하고 해당 AUTO 사이트 장바구니를 다시 구성한다. 이전 창을 열었다는 이유만으로 자동 재구성·주문 완료·로컬 장바구니 제거를 하지 않는다. MANUAL은 원래 상품 URL을 Windows 기본 브라우저에서 순서대로 열며, 결과는 사용자가 확인한다.

파미유 장바구니는 실사이트에서 정상 응답을 확인한 `/affiliate/prdorder`를 연다. 요청에 적힌 `/affiliate/prorder`는 확인 시 HTTP 500이었다.

## AUTO 실행 순서

1. 최신 상품 상태 확인.
2. 주문 대상 확정.
3. 로컬 SQLite 주문 스냅샷/체크포인트 저장 성공 확인.
4. 실제 사이트 장바구니 정리.
5. CafeOrder 주문대상만 다시 담기.
6. 실제 사이트 장바구니 검증.
7. 현재 단계는 여기서 중단하고 사용자가 Edge의 주문/결제를 직접 진행한다.

3번 로컬 저장 실패 시 원격 장바구니를 건드리지 않는다. 실제로 연결된 판매처는 외부 상품 ID·구매 단위·수량·단가를 비교한다. 메가커피·널담은 각 사이트의 비우기 확인창을 검증하고, 파미유는 기존 항목을 상품별로 비운다. 빈 상태를 확인한 뒤 주문 대상을 담는다. 원격 변경이 불명확하면 쓰기를 반복하지 않고 사이트 상태부터 다시 읽어 `UNKNOWN`으로 남긴다. 사이트 장바구니가 일치해도 `READY`일 뿐 주문 완료가 아니며, 이후 주문/결제 단계는 실행하지 않는다.

## 결제 안전과 상태

현재 장바구니 준비 상태: `PENDING`, `PREPARING`, `READY`, `WAITING_FOR_USER`, `FAILED`, `UNKNOWN`. 사용자 화면은 한글로 표시하며, 앱 재실행 시 저장된 스냅샷을 복원하되 이전 READY를 사이트 재확인 전까지 그대로 확정하지 않는다.

결제 제출 가능성이 있으면 무조건 재결제하지 않는다. 성공 페이지를 놓쳤거나 결과가 불확실하면 공급처 주문기록부터 확인한다. 주문 존재가 확실하면 COMPLETED, 주문 부재가 확실하고 재시도가 안전할 때만 재시도 가능, 판단 불가이면 UNKNOWN으로 남긴다.

## AUTO 로그인 유지

AUTO 판매처 5곳에 서로 다른 `%LOCALAPPDATA%\CafeOrder\BrowserProfiles\{판매처ID}` 경로를 할당한다. 현재 실제 로그인 판별은 MegaCoffee·PieceCake·Nuldam에 연결했다. 설치된 Edge의 Playwright persistent context를 사용하며, 재시작 시 사라지는 세션 쿠키는 같은 폴더에 Windows CurrentUser DPAPI로 암호화해 보완한다. localStorage는 브라우저 프로필에 남는다. ID/PW는 판매처관리 입력 후 전송에만 쓰고 저장·출력하지 않는다. 향후 Windows 자격정보 저장소 연결 지점은 `ILoginCredentialSource`다.

앱 시작 시 화면과 로컬 상품/장바구니를 먼저 보여주고 MegaCoffee·PieceCake·Nuldam 세션 확인은 백그라운드에서 실행한다. 로그인 필요 시 버튼으로 Edge를 열고, 인증 화면이나 수동 로그인이 필요하면 `WAITING_FOR_USER` 상태로 브라우저를 유지한다. OTP·QR·CAPTCHA·추가 본인인증은 우회하지 않는다. 나머지 AUTO 판매처는 프로필 경로만 분리했으며 실제 로그인 판별/접속은 후속 검증 전까지 실행하지 않는다.

## 무료배송 설정

판매처에서 기준을 자동 수집하지 않고 CafeOrder 설정값을 사용한다. 초기값은 각 공급처 문서에 둔다. 사용자는 판매처관리에서 수정할 수 있어야 한다. 쿠팡/네이버에는 자동 무료배송 조건을 적용하지 않는다.

AUTO 공급처 소계가 무료배송 기준 미달이면 빨간 비활성 `[N원 부족]`으로 주문을 막는다. 충족하면 초록 `[주문하기]`로 전환한다. 기준 0원은 기본 무료배송이다. 화면의 수량/설정 변경 즉시 다시 계산한다.
