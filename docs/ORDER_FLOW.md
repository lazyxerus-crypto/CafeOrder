# 주문과 로그인 기준

## 로컬 장바구니와 카드

통합 장바구니는 [DATABASE](DATABASE.md)의 로컬 작업목록이다. AUTO 수량 `+/-`는 로컬 DB만 수정한다. 이 동작에서 웹사이트 접속, Playwright 실행, 네트워크 요청을 금지한다.

전체 주문은 [UI](UI.md)의 진행창에서 순차 처리한다. AUTO는 공급처 하나의 주문 가능 상품을 카드 하나로, MANUAL_BROWSER는 상품 URL 하나를 카드 하나로 처리한다. 병렬 결제와 사용자 순서 변경은 없다. 각 카드의 개별 주문도 지원한다.

장바구니의 전체 주문하기는 확인창만 연다. 확인창 하단의 전체 주문하기가 순차 진행을 시작한다. MANUAL 카드에서는 사용자의 사이트 주문 동작을 기다린다. AUTO 무료배송 기준 미달은 개별/전체 진행 모두 주문 불가로 유지한다.

주문 시작 전에는 원래 장바구니 항목을 공유하여 수량 변경/AUTO `+/-` 및 모든 상품의 X 삭제를 즉시 반영한다. 별도 수량 복사본을 만들지 않는다. 개별 주문 시작 시 해당 대상, 전체 주문 시작 시 모든 주문대상의 수량/삭제/추가 변경을 잠근다. 화면뿐 아니라 모델에서도 변경을 막아 진행 중 주문내용이 달라지지 않게 한다. 목업 창을 닫으면 예약된 샘플 전환을 취소하고 편집 잠금을 해제한다.

성공이 확실한 카드만 완료 처리하여 진행창에서 제거하고, 해당 주문만 원래 장바구니에서 제거한다. FAILED/UNKNOWN은 남긴다. MANUAL은 수동 완료 기록 버튼 없이 향후 실제 주문 생성 여부를 자동 확인한다. 확인 불가는 완료로 추측하지 않는다. 세부 경계는 [COUPANG_NAVER](suppliers/COUPANG_NAVER.md)를 따른다.

## AUTO 실행 순서

1. 최신 상품 상태 확인.
2. 주문 대상 확정.
3. 로컬 SQLite 주문 스냅샷/체크포인트 저장 성공 확인.
4. 실제 사이트 장바구니 정리.
5. CafeOrder 주문대상만 다시 담기.
6. 실제 사이트 장바구니 검증.
7. 가능한 가장 빠른 실제 배송일 선택.
8. 체크아웃.
9. 필요한 경우 사용자 결제/인증 대기.
10. 실제 주문 성공 여부 확인.
11. 성공 시 주문기록 저장 및 해당 장바구니 항목 제거.

3번 로컬 저장 실패 시 원격 장바구니를 건드리지 않는다. 최종 장바구니 검증은 기본적으로 상품 식별과 수량만 비교하며 옵션 자체는 비교조건으로 만들지 않는다. 검증 실패 시 자동 재구축은 최대 한 번이다. 두 번째 검증도 실패하면 해당 공급처만 실패시키고 다른 공급처는 계속할 수 있어야 한다.

## 결제 안전과 상태

내부 상태: `PENDING`, `PREPARING`, `WAITING_FOR_USER`, `PAYMENT_IN_PROGRESS`, `COMPLETED`, `FAILED`, `UNKNOWN`. 사용자 화면은 주문 대기, 주문 진행 중, 사용자 확인 대기, 결제 진행 중, 주문완료, 주문실패, 확인필요 같은 한글로 표시한다. 내부 유형/상태 설명을 창 상단에 노출하지 않는다.

결제 제출 가능성이 있으면 무조건 재결제하지 않는다. 성공 페이지를 놓쳤거나 결과가 불확실하면 공급처 주문기록부터 확인한다. 주문 존재가 확실하면 COMPLETED, 주문 부재가 확실하고 재시도가 안전할 때만 재시도 가능, 판단 불가이면 UNKNOWN으로 남긴다.

## AUTO 로그인 유지

AUTO 판매처 5곳에 서로 다른 `%LOCALAPPDATA%\CafeOrder\BrowserProfiles\{판매처ID}` 경로를 할당한다. 현재 실제 접속·로그인 판별은 MegaCoffee 1곳만 연결했다. 설치된 Edge의 Playwright persistent context를 사용하며, 재시작 시 사라지는 세션 쿠키는 같은 폴더에 Windows CurrentUser DPAPI로 암호화해 보완한다. localStorage는 브라우저 프로필에 남는다. ID/PW는 판매처관리 입력 후 전송에만 쓰고 저장·출력하지 않는다. 향후 Windows 자격정보 저장소 연결 지점은 `ILoginCredentialSource`다.

앱 시작 시 화면과 로컬 상품/장바구니를 먼저 보여주고 MegaCoffee 세션 확인은 백그라운드에서 실행한다. 로그인 필요 시 버튼으로 Edge를 열고, 인증 화면이나 수동 로그인이 필요하면 `WAITING_FOR_USER` 상태로 브라우저를 유지한다. OTP·QR·CAPTCHA·추가 본인인증은 우회하지 않는다. 다른 4곳은 프로필 경로만 분리했으며 실제 로그인 판별/접속은 후속 검증 전까지 실행하지 않는다.

## 무료배송 설정

판매처에서 기준을 자동 수집하지 않고 CafeOrder 설정값을 사용한다. 초기값은 각 공급처 문서에 둔다. 사용자는 판매처관리에서 수정할 수 있어야 한다. 쿠팡/네이버에는 자동 무료배송 조건을 적용하지 않는다.

AUTO 공급처 소계가 무료배송 기준 미달이면 빨간 비활성 `[N원 부족]`으로 주문을 막는다. 충족하면 초록 `[주문하기]`로 전환한다. 기준 0원은 기본 무료배송이다. 화면의 수량/설정 변경 즉시 다시 계산한다.
