# Coupang / Naver SmartStore

유형: MANUAL_BROWSER. 통합 장바구니에 포함하며 일반 화면에서는 공급처별로 묶어도 된다. 실제 주문 진행 단위는 기본적으로 상품 URL 하나당 카드 하나다.

## 사용자가 직접 주문

CafeOrder는 `[판매처에서 주문하기]`로 상품 URL을 열어준다. 수량과 옵션은 실제 판매처에서 사용자가 직접 처리한다. CafeOrder에 `1개`를 실제 주문수량처럼 표시하지 않는다.

현재 실제 자동 로그인, 상품 수량 변경, 옵션 선택, 장바구니 조작, 결제, CAPTCHA/anti-bot 우회, OTP 입력, 결제 비밀번호 입력을 자동화하지 않는다.

`[주문완료로 기록]` 버튼은 제거한다. 향후 사용자가 사이트에서 수량/옵션/배송/결제를 직접 처리한 뒤 CafeOrder가 가능한 범위에서 실제 주문 생성 여부를 자동 확인한다. 주문 실행을 대신하지 않으며, 성공을 확실히 확인한 해당 URL 카드만 COMPLETED 처리한다. 확인할 수 없으면 UNKNOWN으로 카드를 유지하고 성공을 추측하지 않는다. 실제 주문번호/최종 금액 등 확인되지 않은 값은 만들지 않는다. 해당 주문의 카드/장바구니 제거는 [ORDER_FLOW](../ORDER_FLOW.md)를 따른다.

현재 목업은 실제 웹 확인 없이 판매처 주문 버튼 → `주문 확인 중...` → 고정 샘플 성공/확인필요만 표현한다. 주문 진행 카드에는 상품 가격과 `수량/옵션: 판매처에서 선택`을 표시하며 임의 수량을 표시하지 않는다.

CafeOrder의 자동 무료배송 조건을 적용하지 않는다. AUTO 원격 장바구니 재구성 및 로그인 유지 자동화 흐름을 적용하지 않는다.

4차 목업의 판매처관리에는 다른 판매처와 같은 ID/PW·로그인 상태·로그인/다시 로그인 UI를 둔다. 입력은 저장·전송하지 않으며 실제 로그인/Playwright 구현은 없다. 실제 자동로그인 지원 가능 여부는 향후 URL 연결 시 확인하고, 지원 불가하면 해당 UI를 변경한다. 현재 자동 주문/무료배송 적용 범위는 그대로다.
