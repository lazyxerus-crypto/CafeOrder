# 화면 기준

메인 탭은 `상품`, `주문기록`, `사이트관리`, `상품추가`, `로그`, `설정` 6개이며 상품이 기본이다. 별도 로그인 탭과 최상단 초록 안내 영역은 없다.

50대 사용자를 위한 큰 글씨·명확한 버튼·낮은 인지 부담을 유지한다. 1280×720과 Windows 100%/125%/150% 배율을 고려하며 불필요한 애니메이션은 금지한다. AUTO/MANUAL/MANUAL_BROWSER는 내부 구분이며 사용자 화면에 표시하지 않는다.

## 상품과 장바구니

- 상단 한 줄: 검색 / 카테고리 / 발주처 / 정렬. 카테고리는 드롭다운이다.
- 왼쪽 상품은 3열 카드. 1:1 이미지 영역에 Zoom을 적용하고, 상품명 3줄 고정 공간 → 판매처 → 가격(PriceText 포함) → 주문가능/품절 → 장바구니에 담기 순서로 표시한다. 품절 담기는 비활성이다.
- 상품명·판매처·가격은 읽기 전용 텍스트 선택/복사를 지원한다. 원문 상품명을 별도 사양 필드로 분해하지 않는다.
- 오른쪽 제목은 `장바구니`. 공급처별 묶음, 각 상품의 1:1 썸네일·상품명·단가를 표시한다. AUTO 수량 버튼은 누를 수 있는 최소 크기를 지키며 한 줄에 배치한다. MANUAL 수량은 표시하지 않는다.
- 무료배송 부족 시 빨간 비활성 부족 금액 버튼, 충족 시 초록 주문하기. 상세 정책은 [ORDER_FLOW](ORDER_FLOW.md).
- 장바구니 전체 주문하기는 확인창을 연다. 진행창에는 사용자용 카드 상태와 AUTO 단가 × 수량/합계, MANUAL 가격/사이트 수량 선택 안내를 표시한다. 하단 닫기/전체 주문하기를 둔다. 순서 변경 UI는 없다.

## 카테고리와 정렬

`전체`, `원두`, `일회용품`, `유제품`, `파우더`, `베이스/농축액`, `시럽/소스`, `과일`, `티백`, `청`, `디저트/스낵`, `기타`.

전체는 필터용이다. 기본순은 카테고리 → 상품명. 선택 정렬은 기본순/이름순/가격순/자주주문한순. 자주주문한순은 실제 구현에서 주문기록만 사용하며 행동 학습을 하지 않는다.

## 나머지 화면

- 주문기록: 주문일시 / 판매처 / 상품 / 결제금액 / 주문번호 / 상태. 복수 상품은 셀 내 여러 줄, 내부 상태는 한글 표시.
- 사이트관리: 공급처명, ID/PW(마스킹), 로그인 상태, 숫자 직접 입력 무료배송 기준, 선호 결제수단. MANUAL에는 자동 로그인 설정 없음. 지원 여부 값으로 네이버 연동 체크박스를 조건부 표시하며 선택 시 직접 ID/PW 입력을 비활성화한다. 미확인 지원을 확정처럼 표시하지 않는다.
- 상품추가: URL 입력으로 공급처 자동 판별, 카테고리 선택, 상품 추가, 공용 ProductCard로 결과 표시. 공급처 선택 ComboBox/별도 등록 버튼 없음. 미지원 주소는 추가 불가. URL 문자열은 복사 가능하다.
- 로그: 읽기 전용 RichTextBox로 드래그 선택 및 Ctrl+C 지원. 추가 필터는 없다.
- 설정: 확정된 백업 기준만 안내한다.

## 2차 목업 범위

24개 가상 상품·가격·주문횟수·주문기록과 캐시한 예시 이미지를 사용한다. 실제 사이트 정보로 주장하지 않는다. 수량/무료배송 기준은 메모리에서만 변경하며 SQLite 저장은 아직 적용하지 않는다. 입력 자격정보는 저장·전송하지 않는다.

쿠팡/네이버 확인 동작은 [COUPANG_NAVER](suppliers/COUPANG_NAVER.md)의 샘플 상태 전환만 구현한다. 초기 파미유 실패/늘담 확인필요를 유지하며, 네이버 빨대 샘플은 확인불가 사례다.

URL 판별은 사용자 제공 도메인 megacoffee.co.kr, piececake.co.kr, foodrain.com, nuldampartners.com, smartstore.naver.com 및 coupang.com을 사용한다. www 변형을 처리하고, 허용 호스트 경계를 검사한다. 우양의 실제 주소는 미제공으로 `wym.example.invalid` 예시만 사용한다. 사이트 접속/로그인/가격 확인은 하지 않는다.

네이버 연동 로그인은 메가커피 한 곳에만 `(예시)` 체크박스로 표시하는 샘플 설정이며 실제 지원 확인을 뜻하지 않는다. 실제 공급처 지원 검증 후 값을 바꾼다.

카드는 최초 생성 후 재사용한다. 탭 전환은 데이터/컨트롤 재생성 없이 처리한다. 필터는 표시/순서만 바꾸고, 수량 변경은 해당 수량·공급처 합계·주문 버튼만 갱신한다. 추가/삭제된 장바구니 행만 구조를 수정하며 스크롤을 유지한다.

실제 DB/사이트/로그인/결제/주문기록 저장/보안 저장소는 구현하지 않는다. 실행과 검증은 [README](../README.md). 실제 POS 및 실제 배율 전환 검증은 별도다.
