# 화면 기준

메인 탭은 `상품`, `주문기록`, `판매처관리`, `로그`, `설정` 5개이며 상품이 기본이다. 사용자 용어는 발주처/사이트 대신 **판매처**로 통일한다. 선택 탭은 본문 배경과 연결하고 색/굵기로 구별한다. 별도 로그인 탭과 상단 안내 배너는 없다.

50대 사용자를 위한 큰 글씨·명확한 버튼·낮은 인지 부담을 유지한다. 1280×720과 Windows 100%/125%/150% 배율을 고려한다. 내부 AUTO/MANUAL 구분은 화면에 표시하지 않는다.

## 상품과 장바구니

- 상단은 카테고리/판매처와 상품 추가·내보내기·가져오기, 그 아래 검색창이다. 좁은 창/큰 글씨에서는 작업 버튼 줄을 나누며 검색 바로 아래 본문이 시작한다. 상품/장바구니는 기존 66:34 2열을 유지한다. 정렬 선택은 없으며 카테고리 고정순 → 상품명 가나다순으로 자동 정렬한다.
- 상품과 장바구니는 옅은 배경/테두리/여백으로 구분하고 헤더 글꼴·높이·여백을 동일하게 한다. 모든 카드에 같은 약한 테두리와 버튼 스타일을 사용한다.
- 상품 카드는 판매처 아이콘/오른쪽 카테고리 → 1:1 이미지 → 상품명 3줄 → 조금 큰 가격 순서다. 설정에서 3/4/5열을 즉시 변경하며 장바구니 폭은 유지한다. 카드별 이름 길이에 관계없이 이미지·이름·가격 위치를 맞춘다. 큰 가격 글씨는 필요한 만큼 줄바꿈한다. 담기 버튼과 드래그 선택 컨트롤은 없다.
- 정상 카드의 좌클릭은 한 번에 수량 +1과 짧은 카드 강조다. 우클릭/이미지 드래그/삭제 상태/Draft는 추가하지 않는다. 품절은 카드 안에 표시하고 AUTO 클릭 시 샘플 재입고/계속 품절만 반영한다. 쿠팡/네이버 자동화 범위는 확대하지 않는다.
- 장바구니는 판매처 아이콘/이름으로 묶고 상품 썸네일·이름·단가·X 삭제를 표시한다. X는 확인창/되돌리기 없이 삭제한다. AUTO만 수량 +/-를 제공한다.
- 담기(기존 상품 재담기 포함) 시 해당 판매처 카드와 그 안의 상품 행을 각각 맨 위로 이동하고 장바구니 스크롤을 상단으로 맞춘다. 방금 담은 행만 약 0.2초 연두색으로 강조하며 판매처 카드 전체/수량 숫자는 강조하지 않는다. 장바구니 내부 +/-는 판매처·상품 순서와 스크롤을 바꾸지 않는다. 이는 일반 장바구니 표시 순서이며 사용자 지정 주문순서 기능은 아니다.
- 무료배송 부족/주문 시작 전 편집/시작 후 잠금은 [ORDER_FLOW](ORDER_FLOW.md)를 따른다. 주문 확인창도 같은 상품 행과 판매처 아이콘을 재사용한다. 진행창 상품 행은 실제 텍스트/썸네일/버튼 높이로 계산하고 수동 상품에 빈 수량 버튼 행을 남기지 않는다. AUTO/수동 카드 모두 내용 높이와 동일한 하단 Padding을 사용한다. 하단 닫기/전체 주문하기는 동일한 기본 크기로 작게 배치한다.
- AUTO 주문하기와 판매처에서 주문하기는 같은 높이·글꼴·Padding을 사용한다.

## 카테고리

`전체`, `원두`, `일회용품`, `유제품`, `파우더`, `베이스/농축액`, `시럽/소스`, `과일`, `티백`, `청`, `디저트/스낵`, `기타`. 전체는 필터용이다. 상품명 원문을 사양 필드로 분해하지 않는다.

## 나머지 화면

- 주문기록: 주문 1건당 카드. 판매처 아이콘/이름·한글 상태·연도 포함 일시·주문번호·상품명/단가/수량/금액·총 결제금액. DataGrid/파란 행 선택 없음. 불확실한 값은 미확인 또는 -.
- 판매처관리: 첫 줄 아이콘/이름·200px ID/PW(비밀번호 마스킹, 영문 입력 모드, 입력/붙여넣기 모두 인쇄 가능한 ASCII만 허용)·실제 지원 대상으로 지정된 경우만 네이버 연동 선택. 둘째 줄 로그인 상태(완료 초록/실패 빨강/확인 전 중립)·숫자 직접 입력 무료배송 기준. 선호 결제수단 UI 없음. 쿠팡/네이버도 같은 ID/PW·로그인 상태·로그인/다시 로그인 UI를 사용한다. 실제 자동로그인 지원 여부는 실제 URL 연결 단계에서 확인하며 미지원이면 그때 UI를 변경한다. 버튼은 연결 준비 안내만 표시한다. 비밀번호 포커스 중 Caps Lock ON이면 `⚠ Caps Lock 켜짐`, OFF/포커스 해제 시 즉시 숨긴다. MANUAL 무료배송 설정은 없다.
- 상품 추가는 별도 탭 없이 상단 버튼으로 여러 Draft를 목록 맨 위에 만든다. 선택 카테고리(전체면 기타)를 적용한다. Draft는 상품 개수/검색/판매처 필터/정렬/장바구니/내보내기에서 제외하며 종료 시 폐기한다. URL Enter 성공은 같은 카드에 샘플 상품을 등록·저장하고 실패는 입력/카드를 유지한다.
- 로그: GPT 등에 복사해 오류를 분석하는 진단 로그. 읽기 전용·선택/Ctrl+C·휠 유지, 전체 복사 버튼 하나만 둔다. 비밀번호/쿠키/세션/토큰/OTP/카드정보/결제 비밀번호를 기록하지 않는다.
- 설정: 기존 백업 안내와 상품 열 개수, 모델리스 글자 크기 상세 설정. 모든 Typography Key를 9~24pt 범위에서 개별 조정하고 전체 화면/높이에 즉시 반영·저장한다. 전체 설정 복사는 Key=값 plain text이며 버튼 자체에 복사 결과를 표시한다.

## 상품 편집과 로컬 설정

- 우클릭 순서: 상품 삭제 → 카테고리 변경(전체 제외 11개) → 구분선 → 이름/가격/이름+가격 복사. 합쳐 복사는 원문 이름 + 줄바꿈 + 가격표시문구를 포함한 가격이다.
- 상품 삭제는 현재 카드에 반투명 빨간 삭제 상태/되돌리기를 표시한다. IsActive=false를 저장하고 다음 실행의 일반 목록에서는 제외한다. 주문기록은 삭제하지 않는다.
- 정상 이미지에 파일 Drop: 원본 중심 정사각 Crop → WebP Quality 80 로컬 저장. 수동 이미지가 예시 웹 이미지보다 우선하며 M 배지를 표시한다. 이미지 메뉴의 수동 이미지 삭제는 파일/이미지만 교체하고 카드/스크롤/순서를 유지한다.
- xlsx는 대량편집 import/export 형식이다. 최소 전달 항목은 상품ID·판매처·상품명·가격·가격표시·카테고리·상품URL·사용여부. IProductWorkbook 경계와 전달 레코드를 두며 현재 버튼은 저장소 연결 전임을 해당 UI에 안내한다. 실제 파일 입출력/SQLite는 구현하지 않는다.
- 토스트 구현·메시지·타이머·예약 공간은 제거했다. 작업 피드백은 카드/행/상태/버튼에서만 제공한다.
- `%LOCALAPPDATA%\CafeOrder\Mockup\ui-state.json`: 열 개수/글자 크기 즉시 저장, 종료 시 창 좌표·크기·최대화 상태 저장. 범위 밖/최소 크기 미만 좌표는 복원하지 않는다. 상품 상태와 수동 이미지 저장 경계는 [DATABASE](DATABASE.md).

## 5차 목업 범위

24개 가상 상품·가격·주문기록과 캐시한 예시 상품 이미지를 사용한다. 판매처 아이콘은 사용자가 제공한 7개 PNG만 사용하며 모든 화면에서 공통 캐시/고정 Zoom 슬롯을 재사용한다. 파일 누락/손상 시 해당 판매처만 기본 placeholder를 표시한다. 매핑/교체 방법은 [아이콘 리소스](../src/CafeOrder/Assets/Sellers/README.md)를 따른다. 실제 상품 정보 조회는 하지 않는다. 수량·배송 기준·완료는 메모리에서만 변경한다. 등록 상품/카테고리/IsActive와 UI 설정·수동 이미지만 최소 로컬 상태로 저장한다. 입력 자격정보는 저장·전송하지 않는다.

판매처관리 로그인 상태는 색상 검토용 샘플이다. 네이버 연동 로그인은 실제 지원 대상으로 확정된 판매처가 없어 현재 모두 숨긴다. 향후 지정 시 SupportsNaverLogin으로 조건부 표시한다.

URL 판별은 사용자 제공 도메인 megacoffee.co.kr, piececake.co.kr, foodrain.com, nuldampartners.com, smartstore.naver.com 및 coupang.com을 문자열로만 검사한다. 우양은 실제 주소 미제공으로 wym.example.invalid 예시만 사용한다. 쿠팡/네이버 샘플 확인 경계는 [COUPANG_NAVER](suppliers/COUPANG_NAVER.md).

판매처관리는 생성한 카드/입력/아이콘을 재사용하고 실제 폭/글자 변경 때만 행 높이를 계산한다. 화면/카드/이미지는 한 번 만들고 재사용한다. 필터는 표시/순서, 수량은 해당 값·소계·주문 가능 여부만 바꾼다. 추가/삭제된 행만 구조를 수정한다. Resize에서는 실제 폭으로 높이와 스크롤 범위를 계산하며 Refresh로 문제를 숨기지 않는다.

실제 DB/로그인/결제/품절 조회/주문 조회/보안 저장소는 구현하지 않는다. 실행과 검증은 [README](../README.md). 실제 POS 및 실제 Windows 배율 전환 검증은 별도다.
